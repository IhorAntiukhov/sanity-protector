# ADR 0001: Boilerplate Stack and Project Structure

## Status

Accepted

## Context

SanityProtector needs a starting point for both its frontend and backend before feature work begins. This ADR records the decisions that cross the frontend/backend boundary or aren't obvious from the code, so contributors don't have to re-derive them from the diff.

## Decision

- **Two independent apps, not a monorepo tool.** `sanity-protector-frontend/` and `sanity-protector-backend/` are separate npm projects with their own pipelines; no workspace tooling was introduced, since the apps only talk over HTTP.
- **Fixed local ports, wired through env vars.** Frontend `3000`, backend `8000`. `NEXT_PUBLIC_API_URL` (frontend) and `FRONTEND_URL` (backend CORS allow-list) are how each app finds the other — change one, update the other.
- **Postgres is provisioned by Docker Compose, not expected on the host.** `sanity-protector-backend/docker-compose.yml` seeds it from `POSTGRES_USER`/`POSTGRES_PASSWORD` in `.env` — never hardcoded in the committed compose file. `npm run start:dev` runs `docker compose up -d` first.
- **The production `Dockerfile` is unrelated to Compose's job.** Compose only satisfies the local Postgres dependency; the app itself still runs on the host during dev. The Dockerfile is for eventually containerizing the compiled app.
- **The compiled entry point is `dist/src/main.js`, not `dist/main.js`.** `prisma.config.ts` and `generated/` live outside `src/`, so TypeScript's inferred build root becomes the project root instead of `src/`. `start:prod` and the Dockerfile's `CMD` both account for this; `tsc`/`nest build` succeed either way, so this only surfaces by actually running the output.
- **Prisma's CLI-installed skill files under `.claude/skills/` are real copies, not the symlinks `prisma init` creates by default** (which point at `.agents/skills/`, a folder this repo doesn't keep). They won't auto-update on a future `prisma init`/`generate`.
- **A repo-root `package.json` exists only to host the Husky pre-commit hook** — Git hooks are repo-wide, and neither app's `package.json` lives at the repo root. The hook brings up Postgres and runs both apps' full test suites before every commit. Its lockfile also made Turbopack misdetect the frontend's workspace root, so `sanity-protector-frontend/next.config.ts` pins `turbopack.root` explicitly.

## Consequences

- Cloning the repo now needs three `npm install` runs (root, frontend, backend) — the root one wires up the commit hook via `prepare`; skipping it means commits aren't gated.
- Committing requires Docker to be running, since the pre-commit hook starts Postgres for the e2e suite.
- Both apps' unit-test suites are currently empty (`--passWithNoTests`); only the Postgres connectivity e2e test is real. Expected for now, but shouldn't persist once feature work starts.
- If `.agents/` or `.windsurf/` ever get regenerated by Prisma, `.claude/skills/` needs a manual re-sync.
